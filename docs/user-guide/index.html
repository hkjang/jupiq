User guide

업무공간과 자원 사용을 한곳에서 확인하세요

Keycloak 로그인부터 실시간 서버 상태, 권한별 이용 통계, 개인 키 회전과 조건부 승인 상태까지 기본 한국어 화면에서 관리합니다.

이 페이지로그인·버전화면 이동내 사용량신선도개인 키요청·승인AI 분석

로그인과 버전 확인

  1. Keycloak로 로그인
    “SSO 로그인”을 선택하고 사내 계정 인증을 완료합니다. 관리자가 SSO를 아직 설정하지 않은 초기 상태에는 로컬 로그인만 표시됩니다.
  2. 첫 화면
    SSO 인증을 마치면 dashboard:read 권한이 있는 계정은 통합 대시보드로 바로 들어갑니다. 만료된 세션에서 특정 화면 주소로 들어왔다면 로그인 후 그 화면으로 되돌아갑니다.
  3. 접근 범위 확인
    처음 보이는 메뉴는 backend가 계정에 부여한 permission에 따라 달라집니다. 대시보드 권한이 없는 계정은 접근 가능한 첫 화면으로 이동합니다.
  4. 버전 확인
    로그인 화면 하단에서 서비스 버전과 commit 요약을, 우측 상단 프로필 컨텍스트 메뉴에서 서비스 버전을 확인할 수 있습니다.

메뉴와 새로고침

좌측 메뉴에서 이동하면 URL에 현재 경로와 주요 필터가 반영됩니다. 브라우저를 새로고침하거나 주소를 공유해도 같은 메뉴와 상세 대상이 다시 열립니다. 뒤로/앞으로 가기도 브라우저 표준 동작을 따릅니다.

  • 긴 관리자 메뉴는 메뉴 스타일과 어울리는 얇은 스크롤바를 사용합니다.
  • 표와 차트의 기본 글자 크기는 가시성을 우선하며 브라우저 확대를 막지 않습니다.
  • 모바일에서는 메뉴 버튼을 열어 동일한 기능에 접근합니다.
  • 권한이 사라진 경로를 새로고침하면 안전한 기본 화면과 사유를 안내합니다.

이용 현황과 서버

대시보드에서 최신 JupyterHub snapshot 기준으로 실행 서버가 있는 사용자 수, 실행 서버, 실행시간, CPU core와 메모리 byte를 확인합니다. 이는 브라우저 로그인 연결 수를 뜻하지 않습니다. GPU 모니터링을 켠 경우에만 GPU Util·VRAM 카드와 메뉴가 나타납니다.

숫자 옆 기준 시각을 확인하세요

실시간 자료에는 마지막 갱신 시각과 신선도가 표시되며 수집에 실패한 Hub는 Degraded 상태가 됩니다.

Fresh

최신

최근 수집 자료입니다.

Stale

지연

마지막 자료는 있지만 기준 시각이 오래됐습니다.

Stale 자료를 현재 사용량으로 단정하지 마세요. 마지막 갱신 시각과 Hub 상태를 확인하고 필요한 경우 관리자에게 알려 주세요.

개인 API 키 생성과 회전

  1. 개인화 → API 키·회전
    키 이름, 본인 permission 안의 scope와 유효기간을 선택해 생성합니다.
  2. 한 번만 표시되는 키 저장
    생성 직후 안전한 비밀 저장소에 옮깁니다. 화면과 API에서 평문을 다시 볼 수 없습니다.
  3. 사용 범위 확인
    키 prefix, scope, 상태, 마지막 사용 시각과 만료일을 확인합니다.
  4. 회전
    회전하면 새 키가 발급되고 이전 키는 같은 transaction에서 즉시 사용할 수 없게 됩니다.
  5. 폐기
    더 이상 사용하지 않거나 의심되는 키를 즉시 revoke합니다.

서버 동작 요청과 승인 상태

관리자가 서버 시작·중지·재시작을 승인 대상으로 설정한 경우에만 승인 메뉴와 Workflow가 나타납니다.

상태의미
요청서버 동작 요청이 생성됨
검토 중팀장 검토를 켠 경우 검토 권한자가 확인
승인승인 권한자가 승인하고 대상 서버 동작 실행
반려동작을 실행하지 않고 사유 기록

Workflow가 꺼져 있으면 승인 메뉴가 표시되지 않고 권한 안의 서버 동작을 바로 수행합니다. GPU·Profile·Storage 같은 카탈로그 요청 자동화는 현재 범위가 아닙니다.

스트리밍 AI proxy

ai:chat 권한과 Provider 설정이 있으면 AI 운영 분석 화면에서 OpenAI-compatible API에 메시지를 보낼 수 있습니다. jupiq는 stream: true로 요청하고 upstream SSE를 브라우저에 전달합니다.

JupyterHub 운영 점검 항목을 한국어로 정리해줘. 아래에 붙여 넣은 사용량 표의 특징을 요약해줘.

관리자는 최대 token을 262,144까지 설정할 수 있지만 Provider와 model의 실제 한도가 우선합니다. 현재 버전은 jupiq DB·Prometheus 자료를 자동 첨부하거나 서버 변경을 Preview·실행하지 않습니다.

LLM 사용량 모니터링은 프롬프트·응답 본문을 수집하지 않지만, 채팅 화면에 직접 입력한 메시지는 응답 생성을 위해 설정된 Provider로 전송됩니다. 민감정보를 입력하지 말고 조직의 데이터 분류 정책을 따르세요.
